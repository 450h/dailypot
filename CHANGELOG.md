# Changelog

All notable changes to DailyPot are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/). Dates are ISO (`YYYY-MM-DD`). Section references (`05 §3`, `ADR-0007`, `F2`) point into [docs/](docs/).

## [0.2.0] – 2026-10-25

The "Broadsheet" release. Driven by three owner complaints about 0.1.0: unlogged days vanished once the nudge was dismissed, the total balance never showed, and cycles could not be extended into the past to add earlier details.

### Added
- **Live main balance and net worth** ([ADR-0007](docs/decisions/0007-anchored-main-balance.md), [05 §10](docs/05-data-model.md)). One optional record, `settings.balanceAnchor = { date, amount }` ("at the start of `date` my main balance was `amount`"), and a derived balance: `anchor + income − daily − non-daily − paid bills − goal contributions − net investment buys` over `[anchor.date, today]`. Nothing derived is stored. Engine functions in `src/shared/engine/balance.ts`: `computeBalance`, `balanceSeries`, `anchorForBalanceNow`, `netWorth`.
  - Set it as "my balance right now is X" from the setup wizard, the dashboard masthead or Settings → Balance; `anchorForBalanceNow` backs out today's flows so the shown figure matches immediately. A past-dated anchor ("As of a different date") is also accepted. Without an anchor the figure is labelled "Change since <first tracked day>".
  - **Net worth** = main balance + savings in **non-archived** goals + portfolio value of **non-archived** holdings. Goals and investments count as money that **left** the main balance, so moving cash into a goal lowers the balance but not net worth. **Archived = closed:** archiving a goal or holding stops its money counting in net worth; the archive confirmation says so.
  - `settings:update` accepts `balanceAnchor` (an object sets it, `null` clears it); the date must be ≤ today (`FUTURE_DATE`) and the amount within ±10,000,000.00 (`INVALID`, shown on the field, never clamped).
- **Extend tracking back** (`cycle:extendBack {startDate, dailyAllowance, confirmDays, skipPastBills?}`, [05 §3](docs/05-data-model.md)). Prepends payday-aligned cycles before the first tracked day. `startDate` must be before the first cycle, ≤ today and at most **1096 days** (about three years) before today (`MAX_EXTEND_BACK_DAYS`). Existing cycles keep their ids, dates and allowance; a short cycle can appear before a mid-month first cycle.
  - `confirmDays` writes a `confirmedDays` entry for every new past day the engine lists as unlogged (`unloggedDays`), so the backfill does not flood the pot history.
  - `skipPastBills` writes a `skipped` settlement (dated today) for every unsettled bill month due in the added range before today (`pastBillsToSkip`); the dialog preview and main share that one definition.
  - The dialog is reachable from the Pot history header and Settings → Budget cycles, with a preview of the cycles it will create and the pot's new opening figure (`planExtendBack`). The IPC command, preload function and channel are new.
- **Unlogged days are confirmable from everywhere**, not only from the nudge: the dashboard **Unlogged days** widget (every closed unlogged day from 7 days before the current cycle to today; it never disappears while a day is unlogged), the **Day Strip** popover on the dashboard and in Pot history (**✓ Spent nothing** / **Add spending**), an inline **✓ Spent nothing** button on each unlogged Pot history row, **Confirm all unlogged in this cycle** in the Pot history header (one `confirmedDays` write per day, cycle-scoped), and a count badge on the **Pot history** sidebar entry. Engine: `unloggedDays(pot, from?, to?)`, newest first.
- **Day Strip** (dashboard ribbon and Pot history): one cell per cycle day, encoded by shape and colour (fed the pot / drew from it / confirmed no-spend / unlogged / today / future), each with an `aria-label`; cells open the matching Pot history row, the confirm popover or the quick add. The ribbon also carries the payday countdown, **Change per-day** and **Salary arrived early?**.
- **Reports:** new chart **Main balance over time** (`balanceSeries`, up to 120 days) with a table view.
- **Settings:** new **Balance** section (current figure, anchor, Set / Adjust / Clear) and **Budget cycles** section (cycle table plus **Extend tracking back**).
- **Setup wizard:** optional **Main balance today** field with an **In credit / Overdrawn** toggle on step 1; it becomes the balance anchor right after setup completes.
- **Dashboard** rebuilt as fifteen widgets ([06 F2](docs/06-features.md)): masthead with a 30-day balance sparkline and a mono ledger, net worth, Day Strip ribbon, today ring with safe-to-spend, side pot with a bill-threshold sparkline, cycle flow, quick add command bar with an 8-second receipt and **Undo**, bills ledger, unlogged days, spending rhythm, savings goals, investments, where it went, nudge footer.
- **Tests:** unit tests **85 → 126** (13 files). New: `src/shared/engine/balance.test.ts`, `src/shared/engine/obligations.test.ts`, `src/renderer/src/components/stripDays.test.ts`, `src/renderer/src/hooks/useCountUp.test.ts`; extended: `cycles`, `pot`, `reports`, `guidance`, `commands`, `store`, `service`. The Playwright suite now covers unlogged-day confirmation (widget, strip cell, **Confirm all**), the dialog focus trap and `inert` background, visible focus on a strip cell and a chart, and an **extend-back → set-balance** case (`tests/e2e/smoke.spec.ts`), plus a layout overflow guard that visits every page at 900×640, 1200×820 and 1440×900 with chart tables and dialogs open (`tests/e2e/layout.spec.ts`).
- **Docs:** [09 Design system "Broadsheet"](docs/09-design-system.md), [10 Renderer components](docs/10-renderer-components.md), [ADR-0007](docs/decisions/0007-anchored-main-balance.md); new screenshots `settings.png` and `dashboard-unlogged.png`.

### Changed
- **"Broadsheet" redesign** of every page ([09](docs/09-design-system.md), [10](docs/10-renderer-components.md)): warm paper / deep ink themes, hairline rules, one ultramarine accent, warm/cool duotone charts, mono datelines over each page title, tabular numerals, status chips with a glyph **and** a word. System fonts only, no new dependencies, light and dark.
- **Entrance choreography on every dashboard visit:** the page remounts (`<Dashboard key={visit} />`) so figures count up, the Day Strip stamps in, ledgers rise and charts draw, within about 1.2 s, on `transform`/`opacity` only. Count-ups pause while a dialog is open or the window is hidden. Under `prefers-reduced-motion: reduce` every figure resolves instantly, Recharts animation is off, and the curtain, ink drop and live-dot pulse are removed.
- **Tables never scroll horizontally.** `.main` is `overflow-x: hidden`; columns marked `data-fold="1|2"` fold away at container widths of 880px and 620px and their information reappears as sub-lines inside the row's primary cell (the "folding ledger", 09 §4.12). The layout e2e test enforces this.
- **`schemaVersion` 1 → 2** ([05 §9](docs/05-data-model.md)). The only shape change is the optional `settings.balanceAnchor`, so the 1 → 2 step is the identity (`MIGRATIONS[1]`): every valid v1 file is already a valid v2 file. On first launch main re-stamps the version, writes `backups/pre-migration-<ts>.json`, then saves. **Downgrade:** an older DailyPot opens a v2 file **read-only** (banner, writes refused, the file is never overwritten). To go back, restore the pre-migration backup.
- `holdingFigures(state, holding, today?)` ignores holding transactions and valuations dated after `today` ([05 §7](docs/05-data-model.md), rule 8 clock safety). Every figure in the app passes `today` (net worth, Investments, dashboard, Reports); only a holding's History dialog still lists every record.
- The main window's pre-paint `backgroundColor` is `#0f0f11` to match the ink theme.
- Docs updated to the shipped behaviour: [05](docs/05-data-model.md) (§2 settings, §3 extend back, §7, §9 migration and downgrade note, new §10), [06](docs/06-features.md) (rewritten as shipped in 0.2.0), [08](docs/08-roadmap-and-risks.md) (v0.2.0 subsection, testing strategy), [04](docs/04-architecture.md) (data-format row), [GLOSSARY](docs/GLOSSARY.md) (main balance, balance anchor, net worth, extend tracking back), [OPEN-QUESTIONS](docs/OPEN-QUESTIONS.md) (D12–D15), [docs/README](docs/README.md) and [decisions/README](docs/decisions/README.md); README features table, tour and FAQ; every screenshot regenerated in light and dark.

### Fixed
- **Cycle flow "returned" figures.** A goal withdrawal or holding sale during the cycle is cash that came back. The legend now prints the engine's signed figures (for example `Saved −500.00`) plus a `Returned` row, and the sentence reads "You kept X of Y this cycle (incl. Z returned from goals or holdings)" with Y = income + returned, so X never exceeds Y. Only the bar clamps its segments at 0.
- **Accessibility, from the review:**
  - Dialogs are `role="dialog" aria-modal="true"` with initial focus, a Tab / Shift+Tab focus trap, and the page behind (`#root`) made `inert` until the last dialog closes; focus returns to the opener afterwards, and a state push from main while a dialog is open no longer moves focus back to the first field.
  - Visible keyboard focus on Day Strip cells (2px solid outline with a halo; variants for "drew" and "today" cells) and on chart surfaces (`.recharts-surface:focus-visible`).
  - Counting numerals are `aria-hidden` while they animate, with the settled value in an `sr-only` span, so screen readers never read intermediate numbers. Status glyphs are `aria-hidden` beside a plain word.

### Security
- **Electron 44.7.0 → 44.9.3.**
- `npm audit fix`: `undici` 7.30.0 → 7.30.1 and 6.29.0 → 6.29.1 (nested under `node-gyp`), `fast-uri` 3.1.8 → 3.1.9. `npm audit --audit-level=high` reports 0 vulnerabilities.
- The new `cycle:extendBack` command and the `balanceAnchor` patch are validated in main with strict zod schemas (`zExtendBackPayload`, `zBalanceAnchor`), refuse future dates (`FUTURE_DATE`) and out-of-range amounts (`INVALID`), and respect the lock state like every other command. The hardened `webPreferences`, CSP, network block and fuses are unchanged; `zod` remains the only runtime dependency; the app still makes no network requests.

## [0.1.0] – 2026-10-13

First release. A free, offline Windows desktop app (Electron 44 · React 19 · TypeScript strict · zod 4 · Recharts 3) built around one habit: a per-day allowance whose unspent money feeds a side pot that pays the monthly bills.

### Added
- **Pot engine** (`src/shared/engine/`, pure and unit-tested): payday-to-payday cycles (payday clamped to the month's length, first cycle up to 62 days in the past, early cycle start when the salary arrives before payday), day deltas that feed or drain the pot, a pot that can go negative, bills paid **nearest due date first** with the pot/main split and shortfall flag, surplus and deficit rolling over between cycles, earmarks, a never-optimistic safe-to-spend figure, and per-cycle reports.
- **Transactions:** daily expenses (count against the per-day), one-off non-daily expenses and income (never touch the pot), with categories, filters and CSV export.
- **Bills:** recurring monthly obligations with a due day, one instance per calendar month, **Mark paid** / **Skip** (waived or paid outside the app), prepayment, and a history showing how much came from the pot and how much from the main balance.
- **Pot history:** every day's per-day, spending, bill payments and running balance, with unlogged days marked and a "No spending logged yesterday" nudge with **Spent nothing**.
- **Savings goals** with progress and "save X per month to reach it by …"; **investment tracker** with net invested, manually entered valuations, gain/loss and "estimated" / "no valuation yet" labels.
- **Reports:** cycle summary with comparison to the previous cycle, spending by category, daily spend vs per-day, pot over time, cycle over cycle and portfolio; every chart has a table view.
- **Local JSON store** in `%APPDATA%\DailyPot` ([ADR-0002](docs/decisions/0002-local-json-storage-and-backups.md)): atomic writes with retry, 14 daily snapshots, pre-import / pre-restore / pre-migration backups, corruption fallback to the newest valid snapshot and a recovery screen when none is valid, forward-only migrations, read-only mode for files from a newer version, import/export.
- **Optional PIN lock** with growing backoff in the main process and auto-lock on idle or the Windows lock screen; light and dark themes following Windows; Arabic notes rendered correctly (`dir="auto"`).
- **No network access at all** ([ADR-0005](docs/decisions/0005-no-network-no-auto-update.md)): no account, cloud, telemetry, ads or auto-update. Hardened Electron: sandboxed renderer, strict CSP, `app://` privileged protocol, named preload functions only, strict zod validation and lock checks in main, Electron fuses.
- **Money as integer minor units** ([ADR-0003](docs/decisions/0003-money-as-integer-minor-units.md)); the **pot is derived, never stored** ([ADR-0004](docs/decisions/0004-derived-pot-ledger.md)); 12 two-decimal currencies (default SAR). MIT licence ([ADR-0006](docs/decisions/0006-license-mit.md)).
- **Packaging and release:** electron-builder NSIS installer and portable exe, CI (typecheck, lint, unit tests, `npm audit --audit-level=high`, build, Playwright smoke test) and a tag-triggered release workflow that attaches `SHA256SUMS.txt`. Unsigned; the README documents the SmartScreen prompt.
- **Docs:** spec, money rules ([05](docs/05-data-model.md)), threat model, security and development frameworks, ADRs 0001–0006, open questions; README with generated screenshots. 85 unit tests and three Playwright e2e tests against the unpackaged build: the smoke walk (setup → expense → pay bill → relaunch), the `app://` hardened-bridge check, and the PIN lock / backoff / recovery flow.
