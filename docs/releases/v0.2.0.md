# DailyPot v0.2.0 — "Broadsheet"

> GitHub release notes. Paste the body below into the `v0.2.0` release; the installer, portable exe and `SHA256SUMS.txt` are attached by the release workflow when the tag is pushed. The full list of changes is in [CHANGELOG.md](../../CHANGELOG.md).

---

DailyPot 0.2.0 answers the three problems found after using 0.1.0 for a cycle: unlogged days could no longer be confirmed once the nudge was gone, the app never showed your actual balance, and there was no way to add the months before you started tracking. The whole UI was rebuilt on a new design system along the way. The money rules, the data folder and the no-network promise are unchanged.

## What's new

**The three fixes you asked for**
- **Unlogged days never vanish.** A day with nothing logged stays visible until you deal with it: an **Unlogged days** widget on the dashboard (current cycle plus the week before), a `?` cell in the new **day strip** that opens **✓ Spent nothing / Add spending**, an inline **✓ Spent nothing** button on each Pot history row, **Confirm all unlogged in this cycle** in the Pot history header, and a count badge on **Pot history** in the sidebar.
- **Live main balance and net worth.** Tell DailyPot your balance once ("my balance right now is X", in the setup wizard, on the dashboard or under Settings → Balance). From then on it is recalculated from every income, expense, paid bill, saving and investment you record, never stored, so editing a past entry corrects it ([ADR-0007](../decisions/0007-anchored-main-balance.md)). **Net worth** = main balance + money in active savings goals + the value of active holdings. Money moved into a goal or holding counts as money that left the main balance; archiving a goal or holding closes it, so its money stops counting. If the figure drifts from your bank app (transfers, fees), set the balance again.
- **Extend tracking back.** **Pot history → Extend tracking back** (also under Settings → Budget cycles) adds payday-aligned cycles before your first tracked day, up to about three years back. You choose the per-day for those days, whether to mark them as "spent nothing", and whether past bill months count as paid before tracking. A preview shows the cycles it will create and what the pot will open at.

**Everything else**
- **"Broadsheet" redesign** of every page: warm paper and deep ink themes, one accent colour, warm/cool duotone charts, tabular numerals, and a dashboard that opens like a front page: the main balance leads, then the day strip, today's ring, the pot, bills, goals and investments. Figures count up and charts draw in each time you open it; under Windows' reduced-motion setting everything appears instantly.
- **Reports:** a new **Main balance over time** chart, with a table view like the others.
- **Settings:** new **Balance** and **Budget cycles** sections.
- **Setup wizard:** an optional **Main balance today** field (in credit or overdrawn).
- **Tables never scroll sideways.** Columns fold into the first cell at narrow widths, down to the 900px minimum window.
- **Accessibility:** dialogs trap keyboard focus and make the page behind inert; keyboard focus is visible on day-strip cells and charts; screen readers hear only the settled figure, never the counting numbers; every status has a glyph and a word.
- **Cycle flow** shows money that came back from a goal withdrawal or a holding sale as a `Returned` row, and "You kept X of Y" never exceeds Y.
- **Electron 44.7.0 → 44.9.3**, plus `npm audit fix` (`undici`, `fast-uri`). `npm audit --audit-level=high` is clean.

## Upgrading

- Install over 0.1.0 (or replace the portable exe). Your data folder (`%APPDATA%\DailyPot`) is kept.
- **The data file moves from `schemaVersion` 1 to 2.** The only change is one new optional setting (the balance anchor), so the migration changes nothing in your data. Before re-saving, DailyPot writes `backups\pre-migration-<timestamp>.json`.
- **Going back to 0.1.0:** an older DailyPot opens a version-2 file **read-only** (you see a banner and writes are refused; the file is never overwritten). To downgrade, restore the `pre-migration` backup via **Settings → Backups & data → Import**, or copy it over `data.json` while DailyPot is closed.
- Set your balance after upgrading to turn the "Change since …" figure into your real main balance; until then the masthead shows the change since your first tracked day.
- The installer is still unsigned: Windows SmartScreen may show "Windows protected your PC". Click **More info → Run anyway**. Verify the download against `SHA256SUMS.txt` with `certutil -hashfile DailyPot-Setup-0.2.0.exe SHA256`.

## Known limitations and open decisions

From [docs/OPEN-QUESTIONS.md](../OPEN-QUESTIONS.md) (decided during this release without the owner; say so if you want them changed) and the risks in [docs/08](../08-roadmap-and-risks.md):

- **D12 — Balance semantics.** Goal contributions and investment buys are treated as cash that *left* the main balance, and an archived goal or holding is treated as closed (it stops counting in net worth). If your goal money sits in the same bank account, "cash" will read lower than your statement. Alternatives: count goals/investments inside the main balance, or keep archived goals counting.
- **D13 — No animations setting.** The dashboard choreography replays on every visit and follows only the OS reduced-motion preference. An `Animations: Match Windows / On / Off` setting would need a `schemaVersion` bump.
- **D14 — Closed cycles stay immutable.** Extend tracking back prepends history, but a closed cycle's per-day or boundaries still cannot be edited; the backfill case is covered by extend-back plus confirmed days.
- **D15 — Widget containment.** Widgets use `contain: layout style` rather than `contain: content`, because paint containment clipped the day-strip popover.
- **Derived balance drift.** Transfers, refunds and fees the app does not model make the main balance drift from your bank; the remedy is re-anchoring ("my balance now is X"), never editing history.
- **Unsigned installer** (D2): SmartScreen warns on first run; checksums are the verification. Revisit if install issues accumulate (checkpoint C4).
- **The PIN locks the screen, it does not encrypt `data.json`** (D3). Forgot it? Close DailyPot and delete `security.json`; your data stays.
- **Windows only** (D6). The code is cross-platform Electron, but only Windows targets are built.
- **Trust checkpoints still open** (C1, C2): logging on ≥ 25 days of the first full cycle, and a hand recomputation of one pot-history day matching the app, both due at the end of the first full cycle.
